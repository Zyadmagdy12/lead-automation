# العينة 1 — Lead Automation: النطاق المثبّت

**بيانات تجريبية فقط (Synthetic). لا توجد نتائج تجارية حقيقية.**

## القرارات المثبّتة

### قنوات الدخول
- **الأساسية:** n8n Form Trigger — فورم ويب بسيط (الاسم، الهاتف، الإيميل، المنتج/الخدمة، الميزانية، الرسالة).
- **الثانية:** WhatsApp Business Cloud — رسالة واردة. تُبنى فقط إذا نجح إعداد رقم تجريبي في Meta؛ وإلا تُستبدل في الديمو بقناة Telegram كمثال دخول ثانٍ، ويُكتب ذلك بوضوح في الـ README. لا واتساب Web غير رسمي، لا أرقام شخصية.
- **الثالثة (قراءة فقط في v1):** Gmail — إيميل استفسار يُحوَّل لليد. لا رد تلقائي من الإيميل في v1.

### CRM
- **HubSpot Free** هو الـ CRM الحقيقي الوحيد. Contact + Deal في Pipeline واحد: New → Qualified → Contacted → Won/Lost.
- Google Sheets **ليست CRM**. استخدامها الوحيد: Dead-Letter Queue عند فشل HubSpot، وجدول Audit Log.
- لا GoHighLevel، لا Zoho في v1.

### HubSpot Authentication — 2026 (محدَّث)
- **الطريقة الصحيحة لـ n8n:** Service Key، تُلصق في n8n كـ App Token / Private App credential. **لا OAuth2، ولا API Key قديم (`hapikey`).**
- لماذا: مفاتيح API أُلغيت في 2022، وإنشاء Private Apps القديمة توقف 26 أكتوبر 2026، وستصبح غير مدعومة في سبتمبر 2027. Service Keys هي البديل الرسمي، بنفس نمط `Authorization: Bearer <token>`، وبدون تاريخ انتهاء افتراضي، وتعمل مع REST API فقط.
- المسار في HubSpot: **Development → Keys → Service keys → Create service key**.
- الـ Scopes المطلوبة فقط، لا أكثر: `crm.objects.contacts.read`, `crm.objects.contacts.write`, `crm.objects.deals.read`, `crm.objects.deals.write`.
- **تحذير مهم:** HubSpot Trigger node في n8n يحتاج credential من نوع Developer App منفصل، وإنشاء Public Apps القديمة توقف في يونيو 2026. لذلك **لا نستخدم HubSpot Trigger في هذه العينة أبداً**. الدخول يكون عبر Form / WhatsApp / Gmail، والمتابعة عبر Schedule Trigger + بحث في HubSpot (Polling).
- لا يُلصق أي Token في المحادثة أو في ملفات المشروع أبداً. يُدخل فقط في مخزن Credentials في n8n.

### التنبيهات
- Telegram Bot للبائع / صاحب العمل: تنبيه فوري لليد Hot، وملخص يومي لليد Warm، وتنبيه فشل تكامل.
- لا إرسال رسائل واتساب تسويقية للعميل في v1.

## قواعد التقييم (Scoring) — 0 إلى 100

| العامل | النقاط |
|---|---|
| ميزانية مذكورة وواضحة | +30 إذا كانت 3000 جنيه أو أكثر، +10 إذا كانت أقل، 0 إذا غابت |
| منتج / خدمة محددة | +20 |
| هاتف + إيميل مكتملان وصحيحا الشكل | +20 |
| رسالة فيها نية شراء واضحة | +20 لنية قوية (عاجل / أبدأ / موعد / تنفيذ)، +10 لسؤال عن سعر / تفاصيل |
| مصدر موثوق (فورم / واتساب) | +10 |

- **Hot:** 70+ **وشرطان إضافيان:** ميزانية 3000+ ونية 10+ على الأقل. بلا أحدهما، الحد الأقصى Warm مهما بلغ المجموع.
- **Warm:** 40–69
- **Junk / Cold:** أقل من 40
- **Incomplete:** بلا هاتف أو بلا منتج — يُسجَّل للمراجعة، ولا يُرسَل تنبيه بيع.

كلمات Junk (تخفض التقييم لصفر عملياً): test / تجربة / وظيفة / CV / قرض / رابط مشبوه / رسالة فارغة.

## قواعد التكرار (Dedup)

تطبيع الهاتف أولاً: إزالة المسافات والشرطات، وتوحيد بادئة مصر `+20` / `0020` / `0` إلى `20`.
تطبيع الإيميل: أحرف صغيرة، وإزالة المسافات.

- هاتف مطابق تماماً بعد التطبيع → مكرر.
- إيميل مطابق تماماً → مكرر.
- هاتف مطابق + اسم مشابه (أول 3 أحرف) → مكرر.
- اسم مشابه فقط بهاتف مختلف → **ليس مكرراً** (اختبار إيجابية كاذبة).
- المكرر: يُدمج في الـ Contact الأصلي في HubSpot، وتُسجَّل المحاولة الجديدة في Audit Log، ولا يُنشأ Deal جديد.
- **Idempotency عند إعادة المحاولة:** قبل أي إنشاء في HubSpot، يُعاد فحص Dedup مرة أخرى. إن وُجد Contact أثناء إعادة المحاولة، يُحدَّث ولا يُنشأ جديد. مفتاح عدم التكرار هو `phone_normalized` أو `email_normalized`، ويُحفظ مع كل ليد في Audit Log.

## SLA والمتابعة

- **Hot:** تنبيه فوري. إن لم يرد البائع خلال 24 ساعة → تذكير Telegram + تسجيل `follow_up_due`.
- **Warm:** تنبيه خلال ساعة. تذكير بعد 48 ساعة إن لم يرد.
- **Junk / Incomplete:** بلا تنبيه بيع. Incomplete يُراجَع يدوياً مرة واحدة.
- في الديمو، الـ 24 ساعة تُحاكى بتاريخ مُقدَّم (لا ننتظر يوماً كاملاً)، ويُكتب ذلك بوضوح.

## معالجة فشل التكامل

- فشل إنشاء Contact/Deal في HubSpot → الليد يُحفظ فوراً في Sheets `Dead_Letter_Queue` مع سبب الفشل والوقت.
- إعادة محاولة 3 مرات (فوري، بعد 5 دقائق، بعد 15 دقيقة) — في n8n عبر Wait + Loop، وفي الاختبار المنطقي عبر محاكاة. **قبل كل محاولة، يُعاد فحص Dedup** لمنع إنشاء مكرر.
- بعد 3 محاولات فاشلة → تنبيه Telegram: "تكامل HubSpot فشل، الليد محفوظ في الطابور، لم يضِع أي ليد".
- **فشل جزئي:** إن نجح إنشاء Contact وفشل إنشاء Deal (أو العكس)، يُسجَّل ما نجح وما فشل في Audit Log، ويُعاد تنفيذ الجزء الفاشل فقط، ولا يُعاد إنشاء الجزء الناجح.
- **فشل Sheets نفسه:** إن فشل الكتابة في Dead-Letter Queue، يُرسَل الليد كاملاً في تنبيه Telegram للبائع / صاحب العمل، مع حفظ نسخة في ملف التنفيذ في n8n (Execution Data). الليد لا يُحذف أبداً بسبب خطأ تقني في أي نظام.
- **القاعدة الذهبية:** لا يُحذف ليد أبداً بسبب خطأ تقني.
